# แนวทางรับ Feedback

สถานะ: แบบร่างสำหรับนำไปใช้กับ bot ในอนาคต
ฉบับเริ่มต้นสำหรับชุดคู่มือใน KM
ยังไม่ได้เชื่อมช่องทางรับเรื่องหรือระบบบันทึกอัตโนมัติ

## ประเภทเรื่อง

| ค่า type | ใช้เมื่อ |
|---|---|
| bug | ฟังก์ชันทำงานผิด ค้าง เปิดไม่ได้ หรือผลไม่ตรงที่คาด |
| feature | เสนอความสามารถใหม่หรือปรับขั้นตอน |
| data | ข้อมูลสนามบิน ทางวิ่ง ชาร์ต NOTAM หรือข้อมูลอ้างอิงผิด |
| documentation | คู่มือไม่ชัดเจน ชื่อปุ่มไม่ตรง หรือขาดขั้นตอน |
| general | ความเห็นทั่วไป |

## ลำดับสนทนา

1. สรุปสิ่งที่ผู้ใช้แจ้งด้วยภาษาง่าย ๆ และเลือกประเภทเรื่อง
2. ถ้าเป็นคำถามวิธีใช้ ให้ค้นคู่มือก่อน; ถ้ายังติดปัญหา จึงเก็บรายละเอียดเพิ่ม
3. ถามครั้งละ 1–2 ประเด็นที่จำเป็น ไม่บังคับให้ผู้ใช้กรอกทุกช่อง
4. สรุปสิ่งที่ทราบ สิ่งที่ยังขาด และวิธีที่ลองไปแล้ว ให้ผู้ใช้แก้ข้อมูลได้
5. เมื่อผู้ใช้ต้องการส่งเรื่องและมีระบบปลายทางเชื่อมไว้ ให้ส่งต่อและรายงานผลจากระบบ
   หากยังไม่เชื่อม ให้สรุปข้อความสำหรับคัดลอกส่งต่อ

## ข้อมูลที่ควรถามตามประเภท

- bug: ทำอะไรอยู่ → คาดว่าจะเกิดอะไร → เกิดอะไรจริง → ทำซ้ำอย่างไร
  ขออุปกรณ์/OS/เบราว์เซอร์, เปิดจากเว็บหรือ PWA, ออนไลน์หรือออฟไลน์ เมื่อเกี่ยวกับอาการ
- feature: อยากทำงานอะไร ปัจจุบันติดขัดตรงไหน และผลลัพธ์ที่ต้องการ
- data: ระบุสนามบิน/จุด/ชื่อชาร์ต/เลข NOTAM, ค่าที่พบ และแหล่งอ้างอิงพร้อมวันที่ถ้ามี
  รับเรื่องได้แม้ผู้ใช้ยังไม่มีหลักฐาน แต่ระบุว่ายังไม่ตรวจยืนยัน
- documentation: ระบุไฟล์หรือหัวข้อ ข้อความที่ไม่ชัด และคำอธิบายที่ต้องการ
- general: เก็บประเด็นและผลกระทบที่ผู้ใช้เล่า

ภาพหน้าจอและไฟล์ตัวอย่างเป็นข้อมูลเสริม ขอเมื่อช่วยอธิบายอาการได้
ใช้ข้อมูลเท่าที่จำเป็นต่อการตรวจปัญหา; ไม่ขอรหัสผ่านหรือ token
ไม่ให้ล้างข้อมูลแอปหรือรีโหลดเป็นขั้นแรกเมื่อผู้ใช้ยังมี GPS track ที่ไม่ได้ EXPORT

## โครงข้อมูลกลางสำหรับผู้เชื่อม bot

นี่เป็นรูปแบบเสนอสำหรับส่งต่อ ไม่ใช่ฐานข้อมูลที่เปิดใช้งานแล้ว
เว้นค่าว่างเมื่อไม่ทราบ และใช้ฟิลด์ที่เกี่ยวข้องกับเรื่องนั้น

~~~yaml
type: bug
summary:
steps: []
expected:
actual:
device:
os:
browser:
mode: unknown
network: unknown
app_version:
source_reference:
attachments: []
attempted_fixes: []
status: collected
issue_url:
~~~

mode ใช้ web / pwa / unknown; network ใช้ online / offline / unknown
app_version เป็นค่าที่ผู้ใช้ทราบหรือระบบตรวจได้ ไม่ให้เดารุ่นจากวันที่แจ้ง
สถานะ collected = สรุปไว้ในบทสนทนาเท่านั้น; submitted = ระบบปลายทางยืนยันการบันทึกแล้ว

## การแจ้งสถานะให้ผู้ใช้

- ยังไม่เชื่อมระบบ: “สรุปเรื่องให้แล้วครับ ยังไม่ได้บันทึกเข้าระบบติดตามงาน”
  พร้อมข้อความสรุปที่ผู้ใช้คัดลอกส่งต่อได้
- บันทึกสำเร็จ: แจ้งเลขอ้างอิง/ลิงก์ที่ระบบส่งกลับจริงเท่านั้น
- บันทึกไม่สำเร็จ: แจ้งว่าการส่งยังไม่สำเร็จและเก็บสรุปไว้ให้ผู้ใช้
- ไม่รับปากว่าจะได้รับการแก้ไขหรือเสร็จเมื่อไรหากผู้ดูแลยังไม่ยืนยัน

## ส่งต่อผู้ดูแล

[ข้อเสนอ] ใช้ GitHub Issues เป็นระบบติดตามงานเมื่อเลือกช่องทาง bot แล้ว
บั๊กแอป/คู่มือส่ง AirNavFlow; ข้อมูลส่วนกลางส่ง DataBase ตามขอบเขตใน [CONTEXT.md](../CONTEXT.md)
เมื่อแก้ข้อมูล/โค้ด ให้ดำเนินการผ่าน PR ตามกติกาโปรเจกต์
เอกสารฉบับนี้ไม่ได้เปิด Issue หรือส่ง feedback อัตโนมัติ
